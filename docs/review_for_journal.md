## 2. 对照期刊验收标准逐条评估

### 标准 1｜方法学对比：**部分满足，但对比本身有形式问题**

已有 `run_09_benchmark_real` / `run_10_benchmark_ext`（8 张双队列），
对比了 CAF 密度、邻域富集、Ripley's L、T-to-core 距离、T 浸润比例。
方向是对的，但读 `results/validation/benchmark_ext.json` 有两处会被抓：

- `z_dens` 与 `z_tinf` 在 8 张里有 5 张是 **NaN**，其余是 **−1.0**。
  原因是"空间重排"不改变全局组成，所以密度/浸润比例的零分布方差为 0。
  也就是说"组成类指标对重排完全不敏感"是**定义上必然**，不是实验发现。
  写进 Results 会被审稿人指出"这是恒等式不是对比"。它只能作为 sanity check。
- 同一个量在两处数值不一致：MEL01 的 B_cell 重排 z 在
  `benchmark_ext.json` 是 **13.0**，在 `counterfactual/MEL01.json` 与
  `fdr_correction.json` 是 **14.9**。审稿人一旦交叉核对就会问哪个是真的。

**缺口**：没有与任何**空间域/空间聚类工具**（Banksy、SpaGCN、Squidpy 的
`nhood_enrichment`/`ligrec`）做同层次比较，也没有与免疫排斥打分
（如 TIDE 的 exclusion 分量、CAF-TGFβ 签名）做头对头。Bioinformatics/BIB 的
方法学审稿人几乎必问"你的最小割相对 Banksy 的空间域边界多了什么"。

### 标准 2｜统计严谨性：**不满足**

- FDR 已做（`_fdr_correction.py`），但**检验族划分不合理**：
  S1 把同一张切片的 fixed/follow 两模式当 16 个独立检验；
  S2 把同一张切片的 k=3/5/8/12 当 32 个独立检验（节点集互相嵌套，强相关）。
  正确做法是每张切片先合成一个检验统计量，family 大小 8。
- **置换次数两个队列不一致**：MEL 的 `n_perm=500`（p 下限 0.001996），
  CSCC 的 `n_perm=150`（p 下限 0.006623）。config 里写的是 500。
  这意味着 CSCC 的"显著"全部卡在分辨率下限上，且没有在任何地方声明。
- **通篇没有效应量的置信区间**。S1 报的是 z=14.9，但真实值 0.0308 与零分布
  均值 0.0136 的比值只有 **2.27×**——z 大是因为零分布 std 只有 0.0012。
  只报 z 不报比值与 CI，是审稿人最容易抓的表述夸大。
- 参数敏感性网格**只跑了 MEL01 一张**（`bmab_sensitivity.json` 的 `slide` 字段），
  却在骨架里表述为全局稳健性。

### 标准 3｜生物学可解释性：**基本满足，但结论方向可能要改**

## 3. 三个阻断级问题（必须先解决才能写正文）

### B1｜R3「解耦」的证据方向是反的 —— 致命

**骨架 R3 写的**：控制距血管距离后，B_cell 与 B_mAb 在 7/8 切片显著负偏相关
（ρ ∈ [−0.25, −0.06]），解离区占比 5.5–8.2%。

**产物里实际是什么**：

`results/validation/decoupling.json`（骨架引用的那些负数的来源）逐条写着：

```
"controlled": false,   "rho_partial": NaN,   "p_partial": NaN
```

它由 `run_06_validate.py --dim decoupling` 生成，代码是：

```python
proxy = 0.5 * (ECM_core_n + CAF_n)          # ← 用局部 ECM/CAF 当 B_cell 代理
d = decoupling_stats(proxy, b["b_mab"], q=...)   # ← 根本没传 control
```

也就是说那些 −0.06 / −0.13 / −0.11 / −0.003：
1. **不是偏相关**，是完全未校正的原始 Spearman；
2. 用的是 `validate.py` 自己的 docstring **明文禁止**的 ECM/CAF 局部代理
   （"不要用局部 ECM/CAF 分数当逐点代理"）；
3. 只有 MEL 4 张（CSCC 那 4 个负数在仓库里找不到对应产物，
   `_cross_cohort_summary.py` 读的就是这个只含 MEL 的文件，
   却把标题印成"控制距血管距离"）。

**真正按论文描述算出来的偏相关**在 `results/validation/screen_decision.json` 里，
由 `run_07_screen.py` 用 `compute_b_cell_field` + `control=d_vessel_um` 算出：

| 切片 | ρ（未校正） | **ρ_partial（控制距血管距离）** | frac_discordant_r |
|---|---|---|---|
| MEL01 | +0.272 | **+0.191** | 4.5% |
| MEL02 | +0.129 | **+0.044** | 5.5% |
| MEL03 | +0.168 | **+0.128** | 4.4% |
| MEL04 | +0.295 | **+0.120** | 4.2% |
| CSCC01 | +0.327 | **+0.382** | 1.7% |
| CSCC02 | +0.184 | **+0.231** | 3.2% |
| CSCC03 | +0.199 | **+0.252** | 2.9% |
| CSCC04 | +0.246 | **+0.204** | 3.6% |

**8/8 为正。** 方向与骨架写的完全相反。

而且解离区占比这个数字本身也在打脸：`decouple_q = 0.75`，在两个屏障**独立**时，
"低 B_cell 且高 B_mAb"的期望占比就是 0.25 × 0.25 = **6.25%**。
实测 1.7–5.5%（校正后）与 5.5–6.7%（未校正）**全部 ≤ 随机期望**。
换句话说，解离区不但不富集，还比随机更少——这是正相关的又一个直接证据。

**这条不是可以"修"的**。正确算法已经在跑，结果就是正相关。可选的出路只有
README「已知的核心风险」里早就写好的那条：把叙事从 GO 改成 PIVOT
（"两道屏障在皮肤肿瘤中高度耦合，耦合源是 ECM 而非几何深度"）。
README 说得很对：这同样是可发表的澄清性结论，且全部支撑证据都已具备。

**顺带一个方法学解释**（也是重构建议）：`compute_b_cell_field` 用的是
`cost = 1/capacity` 的 Dijkstra 最短路。这正是项目自己在 CLAUDE.md
"已被抓出来的三个真 bug"第 2 条里为 B_mAb 修掉的那个毛病——
**最短路允许免费绕开屏障**。B_cell 的切片级标量用的是最小割（拓扑量），
但解耦分析用的逐点场却是最短路（非拓扑量），两者不是同一个数学对象。
这既削弱了"最小割"的叙事一致性，也很可能是 B_cell_field 与 CAF 密度相关
0.32–0.55、与 B_mAb 正相关的原因之一。

### B2｜S2 的效应量是 `k` 与割集规模不匹配的伪影 —— 高，且可修

`configs/default.yaml` 的 `s2.k_list = [3, 5, 8, 12]`，这个取值是给合成图
（25×25，割集 40–76 个节点）设计的。真实切片的割集大得多：

| 切片 | 割集节点数 | k=3 占比 | k=12 占比 | ratio_vs_in_cut (k=3→12) | p (k=3→12) |
|---|---|---|---|---|---|
| MEL01 | 614 | 0.5% | 2.0% | 1.019 → 1.015 | 0.099 → 0.238（**全不显著**） |
| CSCC03 | 247 | 1.2% | 4.9% | 1.086 → 1.301 | 0.049 → 0.024 |
| CSCC04 | 156 | 1.9% | 7.7% | 1.067 → 1.162 | 0.122 → 0.024 |

规律非常清楚：**割集越大，测到的效应越小**。在 614 个节点的封锁带上拿掉
连续的 3 个节点，当然什么都不会发生——这不是"拓扑假设不成立"，
而是实验设计里的 `k` 没有随割集规模缩放。合成图上同一实验的效应是
**7.45×**，真实数据上退化到 **1.02–1.30×**，这个落差不是生物学。

骨架里"32/32 方向一致、中位 ratio=1.067"因此是被稀释过的结论：
方向一致在效应量只有 1–3% 时几乎没有信息量。

**修复**：把 `k_list` 从绝对数改成割集比例（建议 `k_frac: [0.05, 0.10, 0.20, 0.30]`，
即拿掉封锁带 5%–30% 的连续弧），重跑 `run_05` 的 S2。成本是 CPU 分钟级
（每张切片 4 个 k × 200 次随机对照 × 一次最小割）。
这是**全部待办里性价比最高的一项**：它要么把 R4 从"方向一致但效应微弱"
救成真正的结论，要么给出一个干净的阴性结果——两种都比现在的表述可辩护。

**注意**：这一改会改变已发布的 S2 数字。但 S2 目前在骨架里已被降级为
"屏障连续性辅助证据、不承担主论证"，所以不触碰"数字地基"红线；
且旧结果保留即可对照。

### B3｜"交联主导 96–98%" ≈ 把 `beta=3` 换个说法 —— 高

读 `results/validation/bmab_sensitivity.json` 的 `lam_x_beta` 网格
（行 = beta 0.25→12，列 = lam 0.5→20），交联占比是这样的：

| beta | 0.25 | 0.5 | 1.0 | 1.5 | 2.0 | **3.0（默认）** | 4.5 | 6.0 | 9.0 | 12.0 |
|---|---|---|---|---|---|---|---|---|---|---|
| 交联占比（lam=3.0 列） | 0.22% | 1.31% | 12.5% | 56.6% | 84.0% | **97.7%** | 97.0% | 96.7% | 94.3% | 89.6% |

交联占比几乎**只是 beta 的单调函数**，跨 4 个数量级从 0.2% 走到 98%。
`beta` 在 config 里标的身份是 `[无监督标定]`，但它实际上既没有被标定
（没有任何切片间一致性优化的记录），也无法被数据标定——因为：

**尺寸排阻公式作用在一个无量纲的秩上。** `crosslink` 是**片内秩标准化**到 [0,1]
的分数，而 `xi = xi0 · exp(−beta · x)` 是一个有纳米单位的物理式。代入
xi0=20、beta=3 得到：**每一张切片的网孔尺寸范围都被强制成 [1.0, 20] nm**，
与该切片真实的交联水平无关。排阻阈值 r ≥ xi 出现在
`x ≥ ln(20/5.5)/3 = 0.430` —— 也就是说**任何切片、无论生物学如何，
都有约 55–60% 的边被完全排阻**（因为秩分布是均匀的）。
   这个占比可用 `scripts/run_11_review_diagnostics.py` 在你本机的 `.venv` 里直接核验：
   若 8 张切片的"排阻边%"高度一致，就证明它由秩分布而非生物学决定。

后果有两层：
1. §5.1 那段"文献锚定"锚的是纳米单位的物理量，但被锚的输入是无单位的秩，
   锚定链条中间断了。这是审稿人一旦看懂就会致命一击的地方。
2. "B_mAb 变异 96–98% 由交联驱动"因此不是关于皮肤肿瘤的发现，
   而是"我把 beta 设成了 3"的复述。GO 判定（潜力比中位 49.8）同理——
   它由 `frac_crosslink / frac_shared_ecm ≈ 97/2` 直接得出。

**这一条不需要重算，需要重新定性**。三条出路见 §6 决策 C。

## 4. 中等问题（不阻断，但一定会被问）

**M1｜"封锁线"的宽度。** `cut_band_analysis.json` 显示割带占全片 spot 的
6.7%–37.0%（MEL01 = 614/1660 = 37%）。把占三分之一组织的区域称作
"可与病理形态直接对照的封锁线"是站不住的。要么改称"封锁带"并报告其宽度分布，
要么在最小割上做一次瘦身（只保留割边而非割边涉及的全部节点）。

**M2｜S1 的 follow 模式不能"补齐" fixed 模式。** CSCC03 fixed 的零分布均值是
0.0900（z=1.17，不显著），follow 的零分布均值是 0.0137、std 0.0011（z=84.8）。
两个零分布差 6.6 倍——因为 follow 模式把源汇也一起打乱了，
零分布测的是"完全没有空间结构"，而 fixed 测的是"阻力物质的排布"。
**z=84.8 是零分布退化的信号，不是强证据**。骨架用 follow 去救 CSCC03/04 的
fixed 阴性，等于换了个更弱的零假设。诚实写法：fixed 模式 5/8 显著，
follow 模式作为"整体空间结构"的补充检验单独报告，不合并计数。

**M3｜切片级 B_cell 无规模归一化。** B_cell = 1/最大流，而最大流随瘤巢周长
与源汇节点数增长。MEL（0.017–0.040）与 CSCC（0.110–0.138）差 4–8 倍，
两队列的源/汇节点数也差 2–3 倍（MEL01: 133/466；CSCC01: 57/201）。
跨切片、跨队列直接比较 B_cell 数值目前没有可辩护的依据。
建议报告归一化量（如 maxflow / |source|、或 maxflow / 割边数）。

**M4｜Ag_target 只有 2 个基因**（CD274、PDCD1LG2），而 `min_genes_matched=2`
正好卡在下限。抗原贡献恒定在 0.5–1.3%，很可能是"信号太弱测不出"
而非"抗原真的不重要"。这个区别必须在 Discussion 里说清楚，
否则"抗原不重要"是一个没有证据支持的强断言。

**M5｜B_meta 的"物理锚定"用了跳数代理。** `compute_b_meta` 用二值邻接的跳数
× `spacing_um=100`，但建图半径是 150 μm，一跳最远可达 150 μm。
把 `d0_um=130`（氧扩散极限，标注为 `[物理锚定]`）与这个代理距离比较，
误差可达 50%。改用 `D`（真实距离矩阵）做加权 Dijkstra 即可，改动很小。

**M6｜维度③的 AUC 方向是事后选的。** `icb_crosscohort_summary.json` 里
GSE78220 的 `AUC_R_vs_NR = 0.241`，骨架报的 0.76 是取补。方向本身有先验
（屏障高→不响应），但必须在文中写明报的是 AUC(NR vs R) 且方向是先验设定的，
否则连同 GSE91061 的反转一起看，会被读成"挑了个方向"。骨架已把它降级为
Introduction 论据，这个处理是对的，保持。

**M7｜测试覆盖不到统计口径。** 14 个测试全部检验算子的定性行为，
没有一个测试会因为"`decoupling_stats` 忘了传 control"而变红——B1 就是这么
漏过去的。建议补 3 个回归测试（见 §5 R7）。

## 9. 配套的核验脚本

本次审查新增了一个**只读**诊断脚本（不覆盖任何已有产物，只写一个新文件

```bash
.venv\Scripts\python.exe scripts\run_11_review_diagnostics.py ^
    --slides MEL01 MEL02 MEL03 MEL04 CSCC01 CSCC02 CSCC03 CSCC04
```

它一次性核验本报告的三个核心论断：

| 输出列 | 对应论断 | 判读 |
|---|---|---|
| `排阻边%` | §3 B3 | 各片高度一致 → 由秩分布决定，不是生物学信号 |
| `rho_part` | §3 B1 | 为正 → 控制几何后仍耦合，中心主张需改向 |
